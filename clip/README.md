# Clip service

Docker Compose проект для создания вертикальных клипов из локальных MP4 и URL-источников.

## Быстрый старт

```bash
cp .env.example .env
docker compose up --build
```

REST API доступен на `http://localhost:8080`, MCP Streamable HTTP на `http://localhost:8090/mcp`.
Все control-plane запросы требуют заголовок `X-API-Key` (значение `CLIP_API_KEY`).

Для offline разработки можно установить зависимости из `requirements.txt` и запустить:

```bash
uvicorn clip_service.api:app --reload
```

`POST /sources` принимает `kind=local` для существующего MP4 или `kind=youtube` для URL
`youtube.com`/`youtu.be`. Upload endpoint принимает только MP4 и записывает поток с лимитом
`CLIP_MAX_UPLOAD_MB`.

`POST /jobs` без `intervals` строит раскадровку всего источника и рендерит каждый
пригодный эпизод до выбора в Studio. Нужны `CLIP_PERLAPENNA_BASE_URL` и
`CLIP_PERLAPENNA_API_KEY` (OpenAI-compatible vision API), иначе новая задача получает
статус `needs_configuration` и может быть повторена через `/exports/{job_id}/retry`.
Отсутствующий `count` означает весь файл; явно заданный `count` ограничивает число
эпизодов. Раскадровка и ответы модели кэшируются по версии файла и настройкам.
Ручные `intervals` сохраняют прежний цикл одобрения до экспорта.

Локальная студия: `http://localhost:8080/studio/`. При открытии через `localhost` или
`127.0.0.1` доступ подключается автоматически. При доступе по сети требуется
`CLIP_API_KEY`; введённый ключ сохраняется в браузере до нажатия «Забыть ключ».
Панель «Работы» показывает
сохранённые задачи и готовые клипы; по ним можно искать и добавлять их в новый монтаж.
Новый интерфейс построен на браузерном CutWright 0.0.5: доступны дорожки видео и звука,
обрезка, разрезание, переходы, скорость, настройки изображения, текст, субтитры и экспорт.
Проекты и импортированные медиа сохраняются в `storage/studio`; после перезагрузки браузера
откройте проект из списка. Готовые сборки сохраняются в истории проекта. Для браузерного
экспорта используйте актуальный Chrome или Edge и держите вкладку открытой до завершения.

Для пересборки Studio после изменения редактора запустите
`studio-editor/scripts/build-studio.ps1` из корня репозитория. Скрипт собирает
браузерный CutWright и копирует его лицензию и уведомления о зависимостях.
Старые экспорты больше не удаляются по сроку хранения; следите за свободным местом.
Если работы разнесены по нескольким прежним SQLite-базам, объедините их одноразовой
командой из каталога `clip` (исходные базы остаются без изменений):

```powershell
$env:DATABASE_URL = 'sqlite:///./gaming-run.db'
$env:CLIP_STORAGE_ROOT = './gaming-run-storage'
$env:PYTHONPATH = '.'
python scripts/import_studio_history.py studio-local.db try-gaming.db
```

Повторный запуск пропускает уже импортированные записи. Библиотека помечает клипы,
чьи MP4 больше не существуют, как недоступные.

Вкладка «Субтитры» импортирует SRT старого клипа или распознаёт речь из выбранной
сборки. Текст и таймкоды редактируются на дорожке субтитров CutWright. Вкладка
«Озвучка» принимает промпт или ручные реплики, интервалы на шкале времени и создаёт
WAV-дорожку, которую можно добавить в монтаж перед финальным экспортом.

Старая панель редакторского отбора доступна в исходнике `clip_service/studio.html`,
но теперь `/studio/` открывает новую студию.
Ручная задача со списком кандидатов имеет статус `awaiting_review`;
для автоматической задачи выбор `keep`/`skip` сохраняется отдельно от состояния MP4.
Панель показывает исходное видео, транскрипт, причины выбора, контекст ±15 с,
позволяет править границы, отклонять с причиной и добавлять интервал вручную.
История хранится в таблице `review_decisions`. Рабочая копия высокого качества
с 15-секундными полями создаётся отдельной кнопкой вместе с вертикальной копией
и редактируемым проектом `.cutwright.json`. Откройте проект в CutWright; на
таймлайне предложен фрагмент, а полный кадр доступен в медиатеке. При приближении к краю исходника
поле закономерно короче 15 секунд.

`POST /clips/{id}/export` разрешён для одобренных клипов и повторного рендера
эпизодов `needs_fix`; автоматические клипы по умолчанию получают вшитые субтитры,
ручные сохраняют прежнюю настройку `campaign_rules.burn_subtitles`. SRT/VTT
хранятся отдельно. После рендера проверяются длительность, H.264, размер,
наличие звука и диагностические сигналы FFmpeg о чёрных/застывших кадрах и тишине.
После ручного монтажа в CutWright передайте локальный путь экспортированного MP4
через панель или `POST /clips/{id}/finalize` с `{"path":"C:\\...\\edited.mp4"}`.
Этот путь проверяет H.264, 1080×1920, длительность и звук и сохраняет результат
отдельно от исходного проекта.

Для операторского или
offline smoke-режима можно передать детерминированные интервалы:

```json
{
  "source_id": "...",
  "intervals": [{"start": 2.0, "end": 22.0}],
  "campaign_rules": {
    "banner": {"text": "Подпишитесь", "height": 140},
    "watermark": {"text": "@channel"}
  }
}
```

После утверждения экспорт содержит вертикальный H.264 MP4 1080x1920, JPEG thumbnail,
SRT, VTT и JSON manifest.

## Локальное озвучивание готового MP4

Озвучивание запускается отдельно после экспорта или принятия монтажа CutWright.
Исходный MP4 не меняется. В Studio выберите готовый клип, режим озвучивания и
создайте черновик. После анализа отредактируйте реплики и таймкоды, сохраните и
утвердите. Сервис создаст отдельные WAV и MP4 в `storage/voiceovers/<id>`.
Если речь не помещается в интервал, статус станет `needs_revision`; сократите
текст или расширьте интервал и утвердите снова.

Можно озвучить и любой готовый локальный MP4 через `POST /voiceovers` с
`{"path":"C:\\Videos\\finished.mp4","mode":"intro"}`. Для готового клипа
используйте `clip_id` вместо `path`. Режимы: `description`, `commentary`, `intro`.
`GET /voiceovers/{id}` возвращает статус и реплики, `PUT /voiceovers/{id}/lines`
редактирует их, `POST /voiceovers/{id}/approve` запускает синтез,
`POST /voiceovers/{id}/retry` повторяет сбой анализа. Артефакты доступны по
ссылкам в ответе и требуют API key или активную Studio-сессию.

Нужны локальные [Ollama](https://ollama.com/download/windows) и модель
`ollama pull qwen3-vl:4b-instruct`, а также `piper-tts` из `requirements.txt`.
На RTX 3050 проверка показала, что 2B даёт слишком общие и повторяющиеся
реплики; 4B выбран как локальный вариант по умолчанию.
Файлы `ru_RU-denis-medium.onnx` и `ru_RU-denis-medium.onnx.json` разместите в
`models/`, скачав из [каталога голосов](https://huggingface.co/rhasspy/piper-voices/tree/main/ru/ru_RU/denis/medium).
Параметры `CLIP_OLLAMA_URL`, `CLIP_OLLAMA_MODEL`, `CLIP_PIPER_MODEL`,
`CLIP_VOICE_GAIN` позволяют изменить локальную конфигурацию.
На Windows запускайте сервис из виртуального окружения с FFmpeg в `PATH`.
При локальном запуске озвучивание выполняется фоновым заданием API; в Docker
`CLIP_VOICEOVER_QUEUE=true` отправляет его существующему Celery worker.
При распространении приложения учитывайте [GPL движка Piper и условия голоса](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/LICENSING.md).

## GPU (Windows / RTX 3050 4 GB)

По умолчанию `auto` выбирает CUDA Whisper (`int8_float16`) и `h264_nvenc`, когда они доступны;
иначе используется CPU (`int8`) и `libx264`. Настройки: `CLIP_WHISPER_DEVICE`,
`CLIP_WHISPER_COMPUTE_TYPE`, `CLIP_VIDEO_ENCODER` и `CLIP_REQUIRE_GPU`. Последняя запрещает
fallback и подходит для CI/smoke-проверки. `/ready` показывает обнаруженные и выбранные backend'ы.

Создайте окружение на Python 3.12, установите зависимости и используйте FFmpeg-сборку с NVENC:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
# CUDA 12 runtime + cuDNN 9 должны быть доступны процессу faster-whisper.
.\.venv\Scripts\python scripts\gpu_youtube_smoke.py
```

Smoke использует `https://www.youtube.com/watch?v=MnO83la9uWc`, выбирает три русскоязычных
фрагмента, требует CUDA/NVENC и записывает `gpu-youtube-smoke-report.json` вместе с артефактами.
